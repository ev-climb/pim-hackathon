# PIM Hackathon Ideas

Внутреннее приложение для сбора идей к летнему хакатону: сотрудник предлагает идею, поддерживает чужие голосом, записывается в команду и оставляет дополнения. Организаторы видят рейтинг с авторами, почтами и поимёнными списками.

**Прод:** https://pim-hackathon.vercel.app/

Вход только через Google и только с рабочих почт `@pimpay.ru` и `@pimsolutions.ru` — домены режет триггер в базе, а не фронт. Организатор — обычный пользователь, чья почта перечислена в SQL-функции `app.is_admin()`; у него дополнительно появляется вкладка «Рейтинг».

Масштаб, из которого выросли все решения: разовый опрос, около тридцати человек, жизнь — две недели. Абстракций «на будущее» здесь сознательно нет.

---

## Что умеет

- **Облако идей:** карточки с категорией, фильтр по категориям, сортировка «Новые» / «Популярные».
- **Голоса:** пять на человека, снимаются и переставляются свободно. Лимит держит триггер базы, обойти его прямым запросом нельзя.
- **«В команду» и дополнения** — без лимита. Дополнения всегда под своим именем, даже у анонимной идеи.
- **Анонимность** скрывает автора от коллег, но не от организаторов.
- **Своя идея правится и удаляется автором.** После правки в углу карточки появляется «изменено»; удаление доступно, только пока на идею не откликнулись коллеги.
- **Модерация:** организатор скрывает идею (не удаляет) и блокирует автора. Скрытие возвращает потраченные на идею голоса в бюджет проголосовавших.

Правила, которые нельзя нарушить, перечислены в [docs/SPEC.md](docs/SPEC.md) §4 — приватность обеспечивается структурой вью, а не фильтрацией в компонентах.

## Стек

Vue 3 (`<script setup>`) + Vite + TypeScript + Pinia + Vue Router. Бэкенда нет: Supabase — Postgres, Google Auth, RLS. Хостинг — Vercel, деплой на каждый push в `main`.

Публичный `anon`-ключ лежит в бандле, так и задумано: данные защищают политики доступа, а не секретность ключа. `service_role` в приложение не попадает никогда.

```
src/api/        единственное место, где живут вызовы Supabase
src/stores/     auth, ideas, admin, toasts
src/components/ карточка, модалки, композер, чипы, тосты
src/views/      LoginView, IdeasView, AdminView
supabase/       schema.sql, миграции, seed.sql, reset.sql, проверки
docs/           SPEC.md — техзадание, SETUP.md — протокол настройки и деплоя
```

## Локальный запуск

Нужен Node.js 20+ и доступ к Supabase-проекту (свой или общий — ключи в разделе Settings → API).

```bash
npm install
cp .env.example .env.local   # вписать URL проекта и anon public key
npm run dev
```

Приложение поднимется на http://localhost:5174.

**Порт закреплён жёстко** (`strictPort` в [vite.config.ts](vite.config.ts)): он прописан в Redirect URLs Supabase, и если Vite молча уедет на соседний, возврат из Google перестанет работать без внятной причины. Занят — освобождать, а не менять на лету; при смене порт правится в двух местах, в конфиге и в настройках Supabase.

Чтобы вход заработал с локальной машины, в **Supabase → Authentication → URL Configuration → Redirect URLs** должен быть `http://localhost:5174/**`. В Google Cloud адрес приложения не прописывается вообще: браузер возвращается на Supabase, а тот перекидывает дальше.

Сборка прода — `npm run build` (сначала `vue-tsc`, потом Vite), просмотр собранного — `npm run preview`.

## База

Схема целиком лежит в [supabase/schema.sql](supabase/schema.sql) и вставляется в SQL Editor четырьмя блоками. На уже развёрнутую базу схема заново не накатывается — для неё есть миграции `supabase/migrate-NN-*.sql`, идемпотентные и с проверочным блоком в конце.

Пошаговый протокол настройки, от пустого Supabase-проекта до прода, вместе со всеми собранными граблями — [docs/SETUP.md](docs/SETUP.md).

Правила из SPEC §4 прогоняются автоматически, 29 проверок на чистой базе:

```bash
docker run -d --name pimtest -e POSTGRES_PASSWORD=pw -v "$PWD/supabase":/sb:ro postgres:17-alpine
docker exec pimtest psql -U postgres -q -v ON_ERROR_STOP=1 -f /sb/test/00-stub.sql
docker exec pimtest psql -U postgres -q -v ON_ERROR_STOP=1 -f /sb/schema.sql
docker exec pimtest psql -U postgres -f /sb/test/01-checks.sql
docker rm -f pimtest
```

Набор вставляет свои данные и рассчитан на пустую базу: повторный запуск в том же контейнере упадёт на дубликате ключа, это не поломка.

Демо-данные для показа приложения — `supabase/seed.sql`, зачистка перед публикацией опроса — `supabase/reset.sql` (профили живых людей там сознательно не трогаются).
